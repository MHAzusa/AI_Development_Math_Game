# 基本設計仕様書

本書では、要件定義で確定した内容を前提として、基本設計で決定する仕様を整理する。

未確定の項目は、本書に記載した内容をもって確定仕様とはしない。
仕様を決定した場合は、必要に応じて `decisions.md` に決定理由とともに記録する。

---

## 1. 基本設計で決定する事項

### 1.1 P1：設計・実装開始前に優先して決定する事項

P1は、決定しないと主要な設計・実装に進みにくい事項。

#### SPEC-001 システム構成

以下を具体化する。

- ブラウザ
- Webサーバー
- データベース
- 各コンポーネントの役割
- コンポーネント間の通信方法
- 開発環境での各コンポーネントの配置

※ 開発時にはWebサーバーとデータベースをローカルPC上で動作させる想定。
※ 将来の配置先は現時点では固定しない。

#### SPEC-002 問題生成方式

以下を具体化する。

- 四則演算の出題ルール
- 括弧の使用ルール
- Easy / Normal / Hardごとの数値範囲
- Easy / Normal / Hardごとの演算の複雑さ
- 負の数を使用する条件
- 割り算を生成する条件
- 有限小数となる割り算の生成方法
- 10問の問題をいつ生成するか
- 同一問題が出題される可能性の扱い
- 問題生成結果が不正な場合の扱い

#### SPEC-003 数値表現・正解判定

要件定義では「数値として同じ値であれば正解」としているため、以下を決定する。

- 問題の正解を内部でどのデータ型・表現で保持するか
- 小数をどのように表現するか
- 問題生成時の数値表現
- ユーザー入力をどのように数値として解析するか
- 許可する入力形式
- 整数・小数・負数の扱い
- 同じ数値を異なる表現で入力した場合の扱い
- 正解判定に使用する比較方法
- 浮動小数点誤差への対策
- 不正な数値入力を確定できない場合のUI

#### SPEC-004 データ構造

ゲーム結果をどのような構造で保持するかを決定する。

- ゲーム結果
- 問題ごとの結果
- 難易度
- 正解数
- 正答率
- 総回答時間
- 問題内容
- ユーザー回答
- 正解
- 正誤
- ゲーム開始時刻・終了時刻を保存するか
- 各データの型
- NULLを許可する項目
- 必須項目
- 一意性
- 主キー・識別方法

#### SPEC-005 データベース設計

以下を決定する。

- 使用するデータベース
- テーブル構成
- 主キー
- 外部キー
- カラム構成
- データ型
- NOT NULL
- CHECK等の整合性制約
- インデックスの必要性
- ゲーム結果と問題ごとの結果の関連方法
- 完了したゲームのみを保存する方法

## 2. 要件定義で確定している前提

基本設計では、以下を変更せずに設計する。

- 1ゲームは10問。
- 10問目の回答完了でゲーム終了。
- 四則演算および括弧を使用する。
- 難易度はEasy / Normal / Hardの3段階。
- 難易度によって問題の難しさを変更する。
- 割り算では小数の答えを許可する。
- 小数の答えは有限小数のみとする。
- 負の数を使用できる。
- スコアは設定しない。
- 結果として正解数、正答率、総回答時間を扱う。
- 回答はキーボードから入力し、Enterキーで確定する。
- Enterキーを押すまでは回答を修正できる。
- 数値として認識できない入力は確定できない。
- 数値として同じ値であれば正解とする。
- 10問目の回答完了までの総回答時間を計測する。
- ゲーム終了後に各問題の問題、ユーザー回答、正解、正誤を確認できる。
- 完了したゲーム結果をWebサーバー側のデータベースに保存する。
- ゲーム途中の状態は永続保存しない。
- ゲーム途中で離脱した場合は結果を保存しない。
- 初期バージョンではユーザー認証・ユーザー識別を行わない。
- 保存結果はゲーム単位で管理する。
- 保存期間を設けない。
- 初期バージョンでは過去の成績閲覧機能を提供しない。
- 対応デバイスはPC。
- 対応ブラウザは主要なPC向けWebブラウザ。

## 3. 基本設計の推奨検討順序

設計項目間の依存関係を考慮し、以下の順番で検討することを推奨する。

1. 問題生成方式（SPEC-002）
2. 数値表現・正解判定（SPEC-003）
3. システム構成（SPEC-001）
4. データ構造（SPEC-004）
5. データベース設計（SPEC-005）
6. 画面構成（SPEC-006）
7. 画面遷移（SPEC-007）
8. ゲーム開始・回答・時間計測（SPEC-008～010）
9. 結果画面・保存処理（SPEC-011～012）
10. 非機能仕様・その他（SPEC-013～015）

特に問題生成方式と数値表現・正解判定は、データ構造やデータベース設計に影響するため、先に検討する。

## 4. 仕様決定時の扱い

本書に記載された「決める事項」は、現時点では未確定である。

ユーザーが明示的に決定した事項のみを確定仕様として扱う。

仕様を決定した場合は、

1. 本書へ反映する。
2. 必要に応じて `decisions.md` に決定内容と理由を記録する。
3. 既存の要件・仕様との矛盾がないか確認する。
4. 必要に応じて `review.md` にレビュー結果を記録する。
